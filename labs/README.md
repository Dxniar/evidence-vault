# Лабораторные работы на основе Evidence Vault

Источник заданий: методические указания PSZI 4304 «Проектирование систем защиты информации», Караганда, 2024. В PDF четыре лабораторные работы.

| Работа | Реализация в проекте | Проверка |
| --- | --- | --- |
| ЛР 1 | Многоразовый пароль и TOTP, предварительный и полный сеансы, запрет повторного кода, блокировка попыток | Изолированный сценарий `verify_auth.py` и тесты входа |
| ЛР 2 | Google OpenID Connect с выбором аккаунта при каждом новом входе, заранее назначенные локальные права; следователь после Google без локального TOTP, администратор и аудитор с TOTP | Изолированные проверки с FakeGoogle и URL Authlib; реальный вход администратора Google + TOTP подтверждён 14.10.2026; новая ветвь следователя ещё требует сквозной проверки |
| ЛР 3 | `append_event`, класс `AuditLog`, 35 типов событий, JSON-диагностика и ротация Docker-логов | `verify_logging.py`, 11 тестов; полный набор проекта — 118 тестов |
| ЛР 4 | Параметры входа и аудит рабочей станции Windows, резервирование и откат | `Set-Lab4Policy.ps1`, результат `results/lab4-windows.json`; оснастка secpol и окна SRP недоступны на Home |

Редактируемые отчёты находятся в `reports/`; исходное содержание — в `content/`. ФИО, группа и преподаватель оставлены для заполнения. Предпросмотры документов не являются отдельными сдаваемыми работами.

При входе по почте и паролю TOTP обязателен для всех ролей. Исключение относится только к подтверждённому Google-входу следователя: роль, активность, версия сеанса и привязанный `google_sub` проверяются сервером. Новому следователю без TOTP доступно его дополнительное подключение в профиле для резервного входа по паролю. Текст `content/lab2.md` обновлён под эту политику; ранее собранный DOCX нужно пересобрать и проверить перед сдачей.

## Повторение проверок приложения

Из корня проекта, PowerShell:

```powershell
docker compose build web
docker run --rm --network none --volume "${PWD}/labs:/srv/app/labs" --volume "${PWD}/tests:/srv/app/tests:ro" evidence-vault-prod-web python labs/verify_auth.py
docker run --rm --network none --volume "${PWD}/labs:/srv/app/labs" --volume "${PWD}/tests:/srv/app/tests:ro" evidence-vault-prod-web python labs/verify_logging.py
docker run --rm --network none --volume "${PWD}/tests:/srv/app/tests:ro" evidence-vault-prod-web python -m unittest discover -s tests -q
```

Эти команды используют SQLite в памяти, искусственные учётные записи и имитацию хранилища. Рабочие Supabase, реальные пароли и файлы доказательств не используются. Выходные JSON не содержат TOTP-секретов, кодов, cookie и ключей OAuth.

## Лабораторная работа Windows

Откройте папку `labs/windows` в Проводнике и запустите `Запустить_ЛР4.cmd`. Подтвердите стандартный запрос Windows. Запуск из обычного сеанса нужен, если запрос UAC из сеанса инструмента не отображается.

Сценарий сохраняет исходные значения и аудит в `labs/private/windows`, затем применяет параметры из задания и читает результат обратно. Системный `APP_LOG_LEVEL` приложения и журнал Windows — разные механизмы. Пароли, очистка журнала, перезагрузка и запрет запуска программ не выполняются.

Для чтения и отката используйте PowerShell администратора на этом же компьютере:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File labs/windows/Set-Lab4Policy.ps1 -Mode Inspect
powershell -NoProfile -ExecutionPolicy Bypass -File labs/windows/Set-Lab4Policy.ps1 -Mode Restore
```

`completed=true` означает завершение сценария; успешное применение требует также `desired_settings_match=true`. При неуспехе результат не заменяется утверждением о выполнении. Полный результат хранится в `results/lab4-windows.json`.

Ручной запуск 14 октября 2026 года в 01:22:47 (Asia/Qyzylorda, UTC+5) завершён: `completed=true`, `desired_settings_match=true`. Проверены пять параметров входа и дополнительный приоритет расширенного аудита. Во всех пяти категориях включены успехи и отказы — 31 подкатегория. Прочитаны свойства Security: 20 МиБ, циклическое хранение; сохранены три события изменения политики 4719. При независимой сверке результат совпал с текущим скриптом, снимком всех 60 подкатегорий и XML событий. Параметры реестра дополнительно прочитаны повторно.

Парсер native CSV учитывает названия с запятыми и сопоставляет все 60 подкатегорий. В PowerShell 5.1 и 7 прошли по пять проверок сохранённых файлов и искусственных примеров. Результат — `results/lab4-parser-verification.json`. Сравнение прежнего отката в этом файле относится к историческому снимку до успешного применения, а не к действующей конфигурации. Свежий результат применения находится в `results/lab4-windows.json`; сверка артефактов — в `results/lab4-independent-check.json`.

Windows 11 Home не содержит `secpol.msc`. Поэтому требуемые в задании экранные формы политики и SRP остаются отдельным невыполненным пунктом для поддерживаемой редакции Windows. Рабочий сеанс не завершается ради снимка нового экрана входа. Технические снимки и интерфейс Evidence Vault не подменяют эти окна.

## Сборка отчётов

`assemble_lab4.py` обновляет содержание ЛР 4 из полученного результата. `build_reports.py` собирает четыре DOCX; `render_reports.ps1` создаёт только внутренние предпросмотры через отдельный Word. Исходные документы пользователя не открываются. Перед выдачей отчётов проверяются все страницы.

В `private/` находятся исходные настройки и полные XML событий Windows с данными учётной записи. Папка исключена из Git и Docker; её нельзя включать в публичный архив. Отчёт использует обезличенные сведения.
